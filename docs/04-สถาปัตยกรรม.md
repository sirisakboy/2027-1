# สถาปัตยกรรม — ออกแบบอย่างไร ทำไมถึงเลือกแบบนี้

```
                                  ┌──────────────────────────────────────────┐
   มือถือ / โน้ตบุ๊ก / CI runner    │            VM คลาวด์ฟรี (Debian 12)         │
   ┌──────────────┐               │                                          │
   │ WireGuard app│──UDP 51820───▶│ wg0 10.8.0.1  ─┐                         │
   └──────────────┘               │                  │  iptables MASQUERADE   │
   ┌──────────────┐               │                  ├──────────────▶ Internet │
   │OpenVPN Connect│──TCP 443────▶│ tun-tcp 10.9.0.1 ┘  (egress eth0)        │
   └──────────────┘    (สำรอง)     │  tun-udp 10.9.1.1                        │
   ┌──────────────┐               │  dnsmasq 10.8.0.1:53                     │
   │  SSH 22/2222 │──────────────▶│  Arena Portal :8443 (TLS→busybox httpd)  │
   └──────────────┘               │                                          │
                                  └──────────────────────────────────────────┘
```

## หลักการออกแบบ

### 1. WireGuard เป็นช่องทางหลัก

| | WireGuard | OpenVPN |
|---|---|---|
| โค้ด | ~4,000 บรรทัด | ~100,000+ |
| Handshake | 1 RTT (NoiseIK) | หลาย RTT + TLS |
| แบตมือถือ | ต่ำกว่ามาก (ไม่มี keepalive ถี่) | สูงกว่า |
| Roaming (เปลี่ยน Wi-Fi↔4G) | เนียน (stateless) | ต้อง reconnect |
| ผ่านไฟร์วอลล์เข้ม | ❌ UDP อาจถูกบล็อก | ✅ TCP 443 ผ่านได้ |

→ ใช้ WG เป็นหลัก แต่ **ต้องมี OpenVPN TCP 443 ไว้เสมอ** เพราะเครือข่ายโรงแรม/องค์กรจำนวนมากบล็อก UDP ทั้งหมด

### 2. ทำไมต้องมี 2 เครื่องมือ VPN ไม่ใช่ตัวเดียว

เพราะปัญหาที่ต่างกัน:
- **WireGuard**: เร็วกว่า, แบตต่ำ, โค้ดเล็ก = attack surface เล็ก
- **OpenVPN**: TCP 443 (ปลอมเป็น HTTPS), มีระบบใบรับรอง/CRL ที่ revoke รายเครื่องได้จริง, ผ่าน DPI ได้บางกรณี (tls-crypt)

ถ้าใช้อย่างเดียว จะติดปัญหา "ต่อไม่ได้เลยทั้งที่ข้างในสมบูรณ์"

### 3. พอร์ตัลเป็น shell + busybox httpd

เหตุผลที่ **ไม่ใช้** Next.js/Node/Python web app บน VM ฟรี:
- RAM 1 GB (GCP e2-micro) — Node ใช้ 100–200 MB ตลอดเวลา
- ต้องมี npm install / update security patch เอง
- ถ้า web app พัง = พังทั้งระบบ

busybox httpd + CGI shell ใช้ RAM ~1 MB และรันด้วย bash ที่มีอยู่แล้ว
Security ที่ทำแทน framework: Basic Auth + throttle + allowlist ชื่อไฟล์ + `valid_peer_name`

### 4. ทะเบียน peers แบบ TSV

`/etc/arena-vpn/peers.tsv` เป็น **แหล่งความจริงเดียว** ทั้ง CLI และพอร์ทัลอ่านไฟล์นี้

```
name  wg_ip  wg_pub  wg_priv_file  ovpn_cn  ovpn_index  created  status  note
```

- ไม่มีฐานข้อมูล = ไม่มี service เพิ่มที่พังได้
- `awk` อ่านได้ทุกที่, backup ง่าย, diff ได้, กู้ด้วยมือได้
- เขียนแบบ atomic (`mktemp` + `mv`) → ไฟล์ไม่มีทางเสียหายกลางคัน

### 5. IP ในอุโมงค์ผูกกันทั้ง 2 ระบบ

`peer wg_ip = 10.8.0.N` → `ovpn ifconfig-push = 10.9.0.N` (และ `10.9.1.N` สำหรับ UDP)
ข้อดี: ดู IP เดียวก็รู้ว่าเป็นเครื่องไหน และเปิด SSH ข้ามช่องทางได้ (WG ล่ม → เข้า OVPN ที่ IP เดิม)

```
laptop  10.8.0.2  ←→ 10.9.0.2 (TCP) / 10.9.1.2 (UDP)
phone   10.8.0.3  ←→ 10.9.0.3 / 10.9.1.3
```

### 6. CA แบบ EC P-256 + openssl ca (ไม่ใช่ easy-rsa)

| | easy-rsa (ของเดิม) | Arena VPN |
|---|---|---|
| สร้าง CRL (revoke) | ต้องรันสคริปต์เพิ่ม | ✅ `openssl ca -gencrl` ในตัว |
| ขนาดคีย์ | RSA 2048 (~1.2 KB/cert) | EC P-256 (~600 B/cert) |
| จำนวนไฟล์ | ca.crt/ca.key/dh/dhparam (นาน) | ca.crt/ca.key/crl + ใบรับรอง |
| dhparam | ใช้เวลาหลายนาที | DHE ไม่ต้องใช้ (ECDHE) |

นี่คือเหตุผลที่ revoke ของโปรเจกต์นี้ "ได้ผลจริงทันที" ไม่ใช่แค่ลบ peer ออกจาก config

### 7. Failover 4 ชั้น

| ชั้น | กลไก | ใช้เมื่อ |
|---|---|---|
| L1 | WG (UDP 51820) | ปกติ |
| L2 | OpenVPN TCP 443 | UDP ถูกบล็อก |
| L3 | SSH หลายพอร์ต + พอร์ตสุ่ม | VPN ล่มทั้งหมดแต่ SSH ยังได้ |
| L4 | Cloud Console (serial/VNC) | SSH พังด้วย |

`doctor --fix` ถูกออกแบบให้เรียกได้จากชั้น L3/L4 (ทำงานแบบ non-interactive)

### 8. ความปลอดภัยที่ฝังไว้

- ไฟล์ config 600, โฟลเดอร์ 700, ทุกอย่างอยู่ใต้ `/etc/arena-vpn`
- `user nobody` / `group nogroup` สำหรับ OpenVPN
- `crl-verify` เปิดใช้ → revoke ได้จริง
- `tls-crypt` → ปิดลายเซ็น OpenVPN จาก DPI
- IPv6 ปิดอัตโนมัติ (กัน traffic รั่ว) 
- `persist-key`, `persist-tun` + การตรวจ `sshd -t` ก่อน reload เพื่อไม่ล็อกตัวเองออก
- พอร์ทัล: Basic Auth + หน่วงเมื่อผิด + ไม่ส่งคีย์ผ่าน API ภายนอก
- `arena-vpn doctor` เตือนถ้า root login เปิดอยู่ / ufw ทับกฎ

### 9. สิ่งที่จงใจ **ไม่** ทำ (trade-off)

| ไม่ทำ | เพราะ |
|---|---|
| Web UI แบบ SPA framework | กิน RAM เกินจำเป็นบน VM 1 GB |
| Multi-user/บัญชี login | "ฉุกเฉิน" ต้องการความเรียบง่าย — อุปกรณ์คือบัญชี |
| Auto-update จาก GitHub | เซิร์ฟเวอร์ VPN ไม่ควรดึงโค้ดเองอัตโนมัติ |
| Obfuscation เต็มรูปแบบ (เช่น obfs4) | เพิ่มความซับซ้อน — ใช้ tls-crypt พอสำหรับงาน dev |
| IPv6 tunneling | ISP ไทยส่วนใหญ่ยังใช้ IPv4, การปิด IPv6 ลดความซับซ้อนและ leak |
