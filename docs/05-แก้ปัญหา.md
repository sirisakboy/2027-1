# แก้ปัญหา — อาการ → สาเหตุ → วิธีแก้

> **ขั้นแรกเสมอ**: `sudo arena-vpn doctor` (จะบอกว่าอะไรเสียก่อนลงมือ)
> ถ้าเข้า SSH ไม่ได้ → เปิด Console ของคลาวด์แล้วรัน `sudo arena-vpn doctor --fix`

## ตารางอาการ

### ต่อ VPN ไม่ติดเลย (มือถือ/คอมขึ้น "connecting" แล้วหมดเวลา)

| สาเหตุ | ตรวจอย่างไร | แก้ |
|---|---|---|
| Cloud firewall ปิดพอร์ตอยู่ | จากเครื่องอื่น: `nc -zv <IP> 443` / `nc -zvu <IP> 51820` | เพิ่ม ingress rule ทั้ง TCP 443 และ UDP 51820 |
| Public IP เปลี่ยน | `sudo arena-vpn status` เทียบกับ IP ที่เขียนใน `.conf` | `sudo arena-vpn doctor --fix` แล้วดาวน์โหลดไฟล์ใหม่ |
| service ตาย | `systemctl status wg-quick@wg0` | `sudo arena-vpn doctor --fix` |
| เครือข่ายบล็อก UDP | ลองต่อ OpenVPN TCP 443 | ใช้ `.ovpn` แทน |
| App ใช้ไฟล์เก่า | ตรวจ `Endpoint =` ในแอป | ลบ profile เก่า → นำเข้าไฟล์ใหม่ |

### ต่อติดแล้ว แต่อินเทอร์เน็ตใช้ไม่ได้ / เว็บค้างครึ่งเดียว

| สาเหตุ | ตรวจ | แก้ |
|---|---|---|
| **MTU ใหญ่เกิน** (พบบ่อยมากบน GCP) | `ping -M do -s 1400 1.1.1.1` ค้าง/error | `sudo arena-vpn config set AVPN_MTU 1360 && sudo arena-vpn apply` แล้วดาวน์โหลดไฟล์ใหม่ |
| IP forwarding ปิด | `cat /proc/sys/net/ipv4/ip_forward` ต้องเป็น 1 | `sudo arena-vpn doctor --fix` |
| NAT หาย | `sudo iptables -t nat -L POSTROUTING -n` | `sudo arena-vpn doctor --fix` |
| ISP เครือข่ายนั้นบล็อก UDP ขนาดใหญ่ | ลอง MTU 1280 | ตั้ง `AVPN_MTU=1280` |

### DNS ไม่ทำงาน (เปิดเว็บด้วยชื่อไม่ได้ แต่ IP ได้)

| สาเหตุ | แก้ |
|---|---|
| dnsmasq ไม่ทำงาน | `sudo systemctl restart dnsmasq` / `sudo arena-vpn doctor --fix` |
| `systemd-resolved` ยึดพอร์ต 53 | สคริปต์ปิดให้แล้ว — ถ้าแก้เอง: `sudo systemctl disable --now systemd-resolved` |
| client ไม่ได้ DNS | ดาวน์โหลด `.conf` ใหม่ (มี `DNS = 10.8.0.1`) |

### เข้า SSH ไม่ได้ (แต่ VPN ยังใช้ได้)

```bash
# จาก console ของคลาวด์
sudo arena-vpn failover status        # ดูพอร์ตที่ฟังอยู่
sudo arena-vpn failover rotate 2      # เพิ่มพอร์ตใหม่ + เปิด firewall
sudo sshd -t                          # ตรวจ config (ต้องไม่ error)
sudo systemctl restart ssh
```

**สาเหตุที่พบบ่อยที่สุด**: แก้ `sshd_config` แล้วรีสตาร์ทโดยไม่ตรวจ → sshd ตาย
สคริปต์ของเราตรวจ `sshd -t` ก่อนทุกครั้งที่แก้

### พอร์ทัลเว็บเปิดไม่ได้

```bash
sudo systemctl status arena-vpn-portal arena-vpn-portal-tls
sudo ss -lntp | grep 8443
curl -k https://127.0.0.1:8443/api/health     # ต้องได้ {"ok":true}
```

- ขึ้น `NET::ERR_CERT_AUTHORITY_INVALID` → ปกติ (self-signed) กด Advanced → Proceed
- ขึ้น 502/timeout → stunnel ตาย: `sudo systemctl restart arena-vpn-portal-tls`
- ต้องการ HTTPS จริง → ใช้โดเมน + Caddy/Cloudflare Tunnel ด้านหน้า (ดู §ท้าย)

### "Out of capacity" ตอนสร้าง VM บน Oracle

- ลอง Availability Domain อื่น (AD-1/2/3)
- ลดสเปกเป็น 1 OCPU/6 GB
- ลอง region ใกล้เคียง (Singapore ↔ Tokyo ↔ Osaka)
- ถ้าจำเป็นจริง: อัปเกรด PAYG (มักได้ capacity ทันที) แล้วตั้ง budget alert

### Oracle ปิดเครื่องเอง / ถูกเรียกคืน (idle)

Oracle เก็บเครื่องที่ CPU/net/mem ต่ำกว่า 20% ติดกัน 7 วัน
```bash
# ทางแก้ระยะยาว: อัปเกรด PAYG (ฟรียังเท่าเดิม + ไม่ถูกเรียกคืน)
# ทางแก้ชั่วคราว: ตั้ง cron เบา ๆ
echo '*/10 * * * * root dd if=/dev/zero of=/dev/null bs=1M count=100 2>/dev/null' | sudo tee /etc/cron.d/keepalive-a1
```

### ต่อได้หลายเครื่องพร้อมกันแล้วช้า

- GCP e2-micro: CPU shared → จำกัดที่ ~20–50 Mbit/s รวม
- ถ้าจำเป็นต้องใช้แบนด์วิดท์เยอะ → ย้ายไป Oracle A1 หรือใช้ 2 เครื่องแยกงาน

### ไฟล์ `.conf` หลุด / เครื่องถูกขโมย

```bash
sudo arena-vpn peer revoke <ชื่อ>     # ตัดทันที + CRL (OpenVPN ด้วย)
sudo arena-vpn peer delete <ชื่อ> --yes
sudo arena-vpn peer add <ชื่อ>ใหม่     # ออกคีย์ชุดใหม่
```
> จำไว้: **ไฟล์ .conf = รหัสผ่าน** ใครถือไฟล์นั้นเข้าเน็ตผ่านเครื่องคุณได้ทันที

## คำสั่งวินิจฉัยเชิงลึก

```bash
# WireGuard
sudo wg show
sudo wg show wg0 latest-handshakes   # ถ้า 0 = ยังไม่เคยเชื่อม
sudo journalctl -u wg-quick@wg0 -n 50 --no-pager

# OpenVPN
sudo tail -f /var/log/openvpn/tcp.log
sudo tail -f /var/log/openvpn/status-tcp.log

# เส้นทาง/ไฟร์วอลล์
sudo iptables -t nat -L -n -v | head -30
sudo ip route
sudo ss -lntup | grep -E '51820|443|8443'

# พอร์ทัล
sudo journalctl -u arena-vpn-portal -n 50 --no-pager
sudo journalctl -u arena-vpn-portal-tls -n 50 --no-pager

# ดิสก์/log บวม
sudo du -sh /var/log/* | sort -h | tail -5
sudo journalctl --vacuum-size=200M
```

## ตัวเลือกเสริม (ถ้าอยากได้ HTTPS จริง / ซ่อน IP พอร์ทัล)

พอร์ทัลเป็น self-signed โดยเจตนา (ไม่ต้องพึ่ง CA ภายนอก)
ถ้าต้องการใบรับรองจริง ให้ใช้ **Cloudflare Tunnel** (ฟรี) ด้านหน้า:

```bash
# บน VM
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o /usr/local/bin/cloudflared
chmod +x /usr/local/bin/cloudflared
cloudflared tunnel login
cloudflared tunnel create arena-vpn
cloudflared tunnel route dns arena-vpn vpn.example.com
cloudflared tunnel run --url http://127.0.0.1:8443 arena-vpn
```

แล้วปิดพอร์ต 8443 ที่ cloud firewall → พอร์ทัลเข้าถึงได้เฉพาะผ่าน Cloudflare
(ข้อดี: ไม่ต้องเปิดพอร์ตใด ๆ เลย; ข้อเสีย: Cloudflare เห็น traffic พอร์ทัล — **VPN เองไม่ผ่าน Cloudflare**)
