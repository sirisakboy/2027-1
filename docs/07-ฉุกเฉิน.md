# โหมดฉุกเฉิน — เมื่อทุกอย่างพังพร้อมกัน

> เอกสารนี้คือ "คู่มือหน้างาน" สำหรับวันที่ VPN ล่มและคุณอยู่นอกบ้าน
> **ปริ๊นต์หน้านี้เก็บไว้** หรือบันทึกใน Notes มือถือ

## ก่อนเกิดเหตุ: 3 อย่างที่ต้องเตรียม (ทำวันนี้)

```bash
# 1. ทางเข้าสำรอง
sudo arena-vpn failover rotate 2        # บันทึกพอร์ตที่ได้ไว้ในโทรศัพท์
sudo arena-vpn failover status

# 2. สำรองข้อมูล (เก็บนอกเครื่อง)
sudo arena-vpn backup /root/vpn-backup-$(date +%F).tar.gz.enc
#    แล้วดาวน์โหลดลง Google Drive/Dropbox ที่เชื่อมไว้

# 3. ไฟล์ client ล่าสุด
sudo arena-vpn peer export laptop ./laptop.zip
#    เก็บ zip ไว้ในโทรศัพท์ 1 ชุด
```

> **ตัวช่วย**: ในพอร์ทัลมีหน้า "เส้นทางฉุกเฉิน" ที่สรุปพอร์ตทั้งหมดให้ดูจากมือถือ

---

## สถานการณ์ A: ต่อ VPN ไม่ได้ แต่ยังมีเน็ต

```
1. ลอง OpenVPN TCP 443 (ถ้าใช้ WireGuard อยู่)
2. ยังไม่ได้ → เปิดพอร์ทัล https://<IP>:8443 ดูสถานะ
3. พอร์ทัลเปิดไม่ได้ → VPN น่าจะล่มทั้งระบบ → ไปสถานการณ์ B
```

## สถานการณ์ B: เข้าเว็บไม่ได้ SSH ก็ไม่ได้

### B1 — Edge/Chrome: ผ่าน Cloud Shell หรือ Console

**Oracle Cloud**
```
Compute → Instances → <เครื่อง> → Console connections → Create local connection
→ Launch console → login (user: ubuntu/opc + รหัสที่ตั้งไว้)
```
ถ้าไม่เคยตั้งรหัส: ต้อง attach boot volume ไปเครื่องอื่นเพื่อตั้ง (ยุ่ง) → แนะนำตั้งล่วงหน้า:
```bash
# ทำตอนปกติ: ตั้งรหัสสำหรับ console
sudo passwd ubuntu
```

**Google Cloud**
```
Compute Engine → VM instances → <เครื่อง> → ปุ่ม SSH (เปิด browser SSH)
หรือ: ⋮ → Connect to serial console (ต้องเปิด metadata serial-port-enable=TRUE)
```
ตั้ง serial console ล่วงหน้า:
```bash
sudo systemctl enable serial-getty@ttyS0
```

**AWS**
```
EC2 → Instances → <เครื่อง> → Actions → Monitor and troubleshoot → Get system log
ถ้าเปิด EC2 Serial Console ใน account settings แล้ว → Connect
```

### B2 — เมื่อเข้า console ได้: ซ่อมด้วย 2 คำสั่ง

```bash
sudo arena-vpn doctor --fix
sudo arena-vpn failover rotate 2
```

`doctor --fix` จะทำให้อัตโนมัติ: อัปเดต IP ในไฟล์ client, เปิด forwarding+NAT,
restart ทุก service, สร้าง SSH พอร์ตสำรองใหม่

## สถานการณ์ C: sshd พัง (แก้ config แล้วเข้าไม่ได้)

```bash
# ใน console
sudo rm -f /etc/ssh/sshd_config.d/10-arena-vpn.conf
sudo sshd -t
sudo systemctl restart ssh
```

## สถานการณ์ D: ดิสก์เต็ม (ทำให้ทุก service ตาย)

```bash
df -h
sudo journalctl --vacuum-size=200M
sudo apt-get clean
sudo du -sh /var/log/* | sort -h | tail -5
```

## สถานการณ์ E: ต้องย้ายเครื่องด่วน (คลาวด์ปิด VM / region ล่ม)

```bash
# เครื่องใหม่ (คลาวด์อื่นก็ได้)
sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/sirisakboy/2027-1.git && cd 2027-1
sudo ./arena-vpn init --yes          # ติดตั้งเปล่า (ยังไม่ต้องตั้งอะไร)
sudo ./arena-vpn restore ./vpn-backup.tar.gz.enc
sudo arena-vpn config set AVPN_PUBLIC_HOST <IP ใหม่>
sudo arena-vpn peer list             # ตรวจว่าอุปกรณ์ครบ
```

ไฟล์ client เดิมยังใช้ได้ **ถ้า** ตั้ง `AVPN_PUBLIC_HOST` เป็นโดเมนแล้วเปลี่ยน DNS
— นี่คือเหตุผลที่แนะนำให้ใช้โดเมน (`vpn.example.com`) ตั้งแต่แรก

## สถานการณ์ F: พอร์ตทั้งหมดถูกบล็อกโดยเครือข่าย (โรงแรม/องค์กร)

```bash
# เช็กว่าพอร์ตไหนผ่านจากเครือข่ายนั้น
for p in 443 8443 2222 80; do nc -zvw2 <IP> $p && echo "TCP $p OK"; done
nc -zvu -w2 <IP> 51820 && echo "UDP 51820 OK"
```
- TCP 443 ผ่าน → ใช้ `.ovpn` (TCP)
- ไม่มีอะไรผ่านเลย → ใช้ 4G hotspot ของมือถือ หรือ Cloudflare Tunnel

## บทเรียน: ทำให้ "ฉุกเฉิน" เป็นเรื่องปกติ

ระบบที่ทดสอบเฉพาะตอนฉุกเฉิน = ระบบที่พังตอนฉุกเฉิน
**ทดสอบเดือนละครั้ง**:
```bash
# ปิด WireGuard ชั่วคราว แล้วพิสูจน์ว่าทางสำรองใช้ได้
sudo systemctl stop wg-quick@wg0
# ต่อด้วย .ovpn → ต้องได้
sudo systemctl start wg-quick@wg0
```
