# บันทึกการตัดสินใจออกแบบ (ADR)

> ทำไมแต่ละอย่างเป็นแบบนี้ — เพื่อให้คนที่มาแก้ต่อ (หรือตัวคุณเองในอีก 6 เดือน) ไม่ต้องเดา

---

## ADR-001: ใช้ WireGuard เป็นช่องทางหลัก

**สถานะ**: ยอมรับแล้ว

**บริบท**: ต้องเลือกโปรโตคอล VPN หลักสำหรับเครื่องขนาด 1 GB RAM

**ตัวเลือก**
1. OpenVPN เท่านั้น — เข้ากันได้ทุกที่ แต่ช้ากว่า ใช้ CPU สูงกว่า
2. WireGuard เท่านั้น — เร็ว/เบา แต่ UDP ถูกบล็อกบ่อย
3. **ทั้งคู่ (WG หลัก + OVPN สำรอง)** ✅

**ผลลัพธ์**: ซับซ้อนขึ้นเล็กน้อย แต่แลกกับการ "ต่อติดเสมอ" ซึ่งเป็นเป้าหมายหลักของโปรเจกต์
ต้องดูแลทะเบียน peer ที่ผูกกัน 2 ระบบ (แก้ด้วย `peers.tsv` เป็นแหล่งความจริงเดียว)

---

## ADR-002: ใช้ EC P-256 + `openssl ca` แทน easy-rsa

**บริบท**: ต้องมีระบบออก/เพิกถอนใบรับรอง OpenVPN ที่ revoke ได้จริง

| เกณฑ์ | easy-rsa | openssl ca |
|---|---|---|
| CRL | ต้องรันสคริปต์แยก | `openssl ca -gencrl` |
| dhparam | ต้องรอหลายนาที | ไม่ต้อง (ECDHE) |
| ขนาด | RSA 2048 | EC P-256 (เล็กกว่า 50%) |
| ความเข้าใจ | ต้องอ่านเอกสาร easy-rsa | ไฟล์ `.cnf` ตรงไปตรงมา |

**ผลลัพธ์**: ใช้ `openssl ca` กับ config ที่สร้างเอง (`lib/ovpn.sh:ovpn_write_cnf`)
ข้อดีสำคัญ: revoke มีผลทันทีเพราะเซิร์ฟเวอร์ใช้ `crl-verify` โดยตรง

---

## ADR-003: พอร์ทัลเป็น shell CGI ไม่ใช้ Node/Python framework

**บริบท**: ต้องมี UI จัดการอุปกรณ์ บน VM 1 GB RAM

**เหตุผลที่ปฏิเสธ**
- Next.js: ต้องมี build step, RAM 150–300 MB, npm audit ทุกสัปดาห์
- Flask/FastAPI: ต้องลง Python venv + gunicorn, RAM 50–100 MB
- **busybox httpd + CGI shell**: ~1 MB, ใช้ bash ที่มีอยู่

**ความเสี่ยงที่ยอมรับ**: ต้องเขียน security control เอง (ไม่มี framework ช่วย)
→ ชดเชยด้วย: `require_auth()` ทุก route, throttle, `valid_peer_name`, allowlist ไฟล์, `--json` output แบบ manual escape

---

## ADR-004: ทะเบียน peers เป็น TSV ไม่ใช่ SQLite

**เหตุผล**
- อ่าน/แก้ด้วยมือได้เมื่อฉุกเฉิน (สำคัญมาก — ใน console ของคลาวด์ไม่มี sqlite3)
- `grep`/`awk` ใช้ได้ทุกที่
- backup = คัดลอกไฟล์
- ไม่มี service เพิ่มที่พังได้

**ข้อจำกัดที่ยอมรับ**: ไม่มี transaction จริง (ชดเชยด้วย atomic write: `mktemp` + `mv`), ช้าเมื่อเกินหมื่นรายการ (ไม่ใช่กรณีใช้งานของเรา: max 8)

---

## ADR-005: OpenVPN TCP และ UDP ใช้ subnet แยกกัน

**บริบท**: OpenVPN farm การแยกอินสแตนซ์หลายตัวบนพอร์ตเดียวกัน

**ทางเลือก**
1. ใช้ subnet เดียวกันทั้ง TCP/UDP → ต่อพร้อมกันได้衝突 IP
2. **แยก subnet**: TCP = 10.9.0.0/24, UDP = 10.9.1.0/24 ✅

**ผลลัพธ์**: ผู้ใช้ต่อได้ทั้งสองช่องทางพร้อมกัน (เช่น มือถือต่อ TCP, โน้ตบุ๊กต่อ UDP) โดยไม่ชน IP
CCD ผูก IP ให้ตรงกันทั้งคู่ (`.N` เดียวกันใน subnet ของตัวเอง) เพื่อให้ `ssh` ไปหาอุปกรณ์ได้ง่าย

## ADR-006: ไม่ทำ multi-user / บัญชี login

**บริบท**: ต้องการระบบ user สำหรับหลายคน?

**ตัดสินใจ**: ไม่ทำ — "อุปกรณ์ = ผู้ใช้" (1 peer = 1 คน/เครื่อง)

**เหตุผล**: เป้าหมายคือ "อุโมงค์ส่วนตัวฉุกเฉิน" ไม่ใช่ VPN สำหรับทีม
ถ้าต้องการหลายคน ให้เพิ่ม peer (สูงสุด 8) และเพิกถอนรายเครื่อง — ง่ายกว่าและปลอดภัยกว่า

**ถ้าต้องการต่อยอด**: เพิ่มฟิลด์ `owner` ใน `peers.tsv` และ filter ในพอร์ทัล

---

## ADR-007: ไม่มี telemetry / phone-home

**ตัดสินใจ**: ไม่มี analytics, ไม่มี update check, ไม่มี crash report

**ข้อยกเว้นที่ต้องมี**: ตรวจ public IP ทุกชั่วโมง (จำเป็นต่อการสร้างไฟล์ client ที่ถูกต้อง)
→ ปิดได้ด้วยการตั้ง `AVPN_PUBLIC_HOST` เป็นโดเมน/IP คงที่

**เหตุผล**: เครื่องนี้ถือคีย์ทั้งหมดของผู้ใช้ การเชื่อมต่อออกโดยไม่จำเป็นคือความเสี่ยง

---

## ADR-008: `doctor --fix` ต้องทำงานแบบ non-interactive

**บริบท**: คำสั่งนี้จะถูกเรียกจาก console ของคลาวด์ ซึ่งไม่มี TTY เต็มรูปแบบ

**ข้อกำหนด**
- ห้ามถามอะไร (`confirm` ต้องไม่ถูกเรียก)
- ห้ามลบข้อมูล (แก้ได้เฉพาะสิ่งที่สร้างใหม่ได้: conf, กฎ, service state)
- ต้องไม่ล็อกตัวเองออก (ตรวจจับ `sshd -t` ก่อน reload เสมอ)
- รันซ้ำได้ (idempotent)

---

## ADR-009: ไฟล์ client ฝังคีย์ inline (ไม่แยกไฟล์)

**ผลลัพธ์**: ไฟล์ `.conf`/`.ovpn` 1 ไฟล์ = ใช้งานได้ทันทีบนทุกแพลตฟอร์ม

**ข้อแลกเปลี่ยน**: ไฟล์ที่หลุด = คีย์หลุดทั้งหมดของเครื่องนั้น
→ ชดเชยด้วย: revoke รายเครื่อง, `peer refresh`, และคำเตือนในทุกคำสั่งที่สร้างไฟล์

---

## ADR-010: เอกสารภาษาไทยเป็นหลัก

**เหตุผล**: ผู้ใช้หลักคือคนไทยที่ต้องการ VPN สำหรับงาน dev — คำอธิบายภาษาอังกฤษ
เรื่อง MTU/firewall/CRL มักทำให้คนเลิกกลางทาง

**โครงสร้าง**: 9 ไฟล์แยกตามสถานการณ์ (เริ่มต้น/แก้ปัญหา/ฉุกเฉิน) ไม่ใช่เอกสารยาวไฟล์เดียว
เพราะเวลาฉุกเฉินต้องหาเจอเร็ว ไม่ใช่ต้องอ่านทั้งหมด
